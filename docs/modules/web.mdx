`continew-starter-web` 是 ContiNew Starter 提供的 Web 开发基础模块，为 Spring Boot Web 应用提供常用能力的自动配置与最佳实践，主要包含以下内容。

- **跨域支持**：通过配置快速启用和定制跨域过滤器 `CorsFilter`；
- **统一响应处理**：内置响应数据封装、全局异常处理、异常别名与国际化，无第三方响应组件依赖；
- **Query 参数转换器**：`Date`、`LocalDate`、`LocalTime`、`LocalDateTime`、`BaseEnum` 类型参数自动转换；
- **服务器增强**：基于 Tomcat 服务器，支持全局禁用不安全的 HTTP 请求方法。

<Callout type="info">
链路追踪（Trace）是独立模块 `continew-starter-trace`，不在本模块中，详见 [Trace 链路追踪](/docs/starter/modules/trace)。
</Callout>

## 引入依赖

```xml
<dependency>
    <groupId>top.continew.starter</groupId>
    <artifactId>continew-starter-web</artifactId>
</dependency>
```

## 跨域配置

前后端分离开发时，跨域是避不开的配置。模块提供了跨域过滤器自动配置（`CorsAutoConfiguration`），配置项对应类为 `top.continew.starter.web.autoconfigure.cors.CorsProperties`，默认不启用。

```yaml
continew-starter:
  web:
    cors:
      # 是否启用跨域配置（默认：false）
      enabled: true
      # 允许跨域的域名（Ant 风格通配符模式，与 allowed-origins 互斥，配置后仅本项生效）
      allowed-origin-patterns:
        - https://*.example.com
      # 允许跨域的域名（默认：*）
      allowed-origins: '*'
      # 允许跨域的请求方式（默认：*）
      allowed-methods: '*'
      # 允许跨域的请求头（默认：*）
      allowed-headers: '*'
      # 允许跨域的响应头
      exposed-headers: '*'
```

<Callout type="info">
当需要携带 Cookie 等凭据信息时，CORS 规范不允许 `allowed-origins` 与 `allow-credentials` 同时为 `*`，此时推荐使用 `allowed-origin-patterns`（如 `https://*.example.com`）进行精确匹配。自动配置会在 `allowed-origin-patterns` 不含 `*`、或 `allowed-origins` 为具体域名时自动开启 `allowCredentials`；预检请求缓存时间（`maxAge`）固定为 1800 秒。
</Callout>

## 统一响应处理

统一响应处理由本模块内置实现，包含响应数据封装、全局异常处理、异常别名与国际化。3.0 起不再依赖 Graceful Response，响应类固定为 `top.continew.starter.web.model.R`。

### 启用统一响应处理

统一响应处理不参与自动配置扫描，必须通过 `@EnableGlobalResponse` 显式启用。

```java
@EnableGlobalResponse
@SpringBootApplication
public class ExampleApplication {

    public static void main(String[] args) {
        SpringApplication.run(ExampleApplication.class, args);
    }
}
```

### 全局配置

配置项对应类为 `top.continew.starter.web.autoconfigure.response.GlobalResponseProperties`。模块已内置一套默认值（见 `continew-starter-web/src/main/resources/default-response.yml`），常用配置如下。

```yaml
continew-starter:
  web:
    response:
      # 是否开启国际化（默认：false）
      i18n: false
      # 失败时的 HTTP 状态码（默认：200，建议业务状态码与通信状态码区分）
      default-http-status-code-on-error: 200
      # 成功响应码（默认：0）
      default-success-code: 0
      # 成功提示（默认：ok）
      default-success-msg: ok
      # 失败响应码（默认：1）
      default-error-code: 1
      # 失败提示（默认：error）
      default-error-msg: error
      # 参数校验失败响应码（默认取 default-error-code）
      default-validate-error-code:
      # 是否打印异常日志（模块默认：true）
      print-exception-in-global-advice: true
      # 是否将原生异常错误信息填充到响应信息中（模块默认：true）
      origin-exception-using-detail-message: true
      # 例外包路径（支持数字、* 和 ** 通配符匹配），该包路径下的 Controller 将被忽略处理
      exclude-packages:
        - io.swagger.**
        - org.springdoc.**
        - org.springframework.boot.actuate.*
```

### 响应结构

响应类 `top.continew.starter.web.model.R` 的结构如下。

```json
{
  "code": "0",
  "msg": "ok",
  "success": true,
  "timestamp": 1691453288000,
  "data": {}
}
```

`success` 由响应码与 `default-success-code` 比较得出，`timestamp` 取序列化时刻。控制器直接返回 `R` 时不会被二次包装。

### 排除统一封装

文件下载等场景需要直接返回原始数据时，在接口方法、控制器类或返回类型上添加 `@ExcludeFromGlobalResponse` 注解即可排除统一封装。

```java
@ExcludeFromGlobalResponse
@GetMapping("/download")
public void download(HttpServletResponse response) {
    // 直接输出文件流
}
```

也可以通过 `exclude-packages`、`exclude-urls`、`exclude-return-types` 按包路径、请求 URL 或返回类型批量排除。返回 `ResponseEntity`、文件流等非 JSON 响应同样不会被包装。

### 异常别名

需要把第三方异常映射为固定响应码时，可使用配置方式：

```yaml
continew-starter:
  web:
    response:
      exception-alias-config-map:
        "[java.lang.IllegalStateException]":
          code: 4001
          msg: 状态异常
          http-status-code: 418
```

也可以在异常类上标注 `@ExceptionAliasFor`，并通过 `ExceptionAliasRegister` 注册：

```java
@ExceptionAliasFor(aliasFor = IllegalStateException.class, code = "4001", msg = "状态异常")
public class IllegalStateAliasException extends RuntimeException {
}
```

```java
@Bean
public ExceptionAliasRegister exceptionAliasRegister() {
    return new ExceptionAliasRegister().doRegisterExceptionAlias(IllegalStateAliasException.class);
}
```

业务方自定义的 `@RestControllerAdvice` 处理器优先于全局异常处理器，二者不会产生重复包装。

### 国际化

开启 `i18n` 后，响应信息会按 `code` 从 `i18n/messages.properties`（或 `i18n.properties`）中查找并替换，未匹配时保留原信息。

```properties
0=操作成功
1=服务器异常，请联系管理员
```


## Query 参数转换器

默认情况下，Spring MVC 无法直接转换 Query 中的日期类型参数，需要使用 `@DateTimeFormat` 注解。

模块内置了 Query 参数转换器（`WebMvcAutoConfiguration#addFormatters`），可自动转换以下类型。

- `java.util.Date`（经 Hutool `DateUtil.parse` 解析，支持多种常见日期格式）
- `LocalDateTime`（默认格式 `yyyy-MM-dd HH:mm:ss`）
- `LocalDate`（默认格式 `yyyy-MM-dd`）
- `LocalTime`（默认格式 `HH:mm:ss`）
- `BaseEnum`（枚举参数自动按编码值匹配）

如果默认格式无法满足要求，仍可使用 `@DateTimeFormat` 注解指定格式。

## Tomcat 服务器增强

模块使用 Spring Boot 默认的 Tomcat 服务器（依赖 `spring-boot-starter-webmvc`），并做了两项增强。

### 全局禁用不安全的 HTTP 方法

配置项对应类为 `top.continew.starter.web.autoconfigure.server.ServerExtensionProperties`（配置前缀为 `server.extension`，非 `continew-starter` 前缀）。

```yaml
server:
  extension:
    # 是否启用（默认：true）
    enabled: true
    # 不允许的请求方式（默认禁用 CONNECT、TRACE、TRACK）
    disallowed-methods:
      - CONNECT
      - TRACE
      - TRACK
```

### Tomcat 线程池默认配置

模块内置了 Tomcat 的部分默认配置（见 `continew-starter-web/src/main/resources/default-server.yml`），可按需在 `application.yml` 中覆盖。

```yaml
server:
  tomcat:
    # HTTP POST 请求内容大小上限（-1 不限制）
    max-http-form-post-size: -1
    threads:
      # 最大工作线程数
      max: 256
```

<Callout type="info">
「全局禁用不安全的 HTTP 方法」由 Servlet 过滤器（`DisallowedMethodsFilter`）实现，不依赖具体容器，Tomcat、Jetty 等 Servlet 容器均生效。
</Callout>
