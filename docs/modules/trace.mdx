---
title: 链路追踪
description: 基于 Micrometer Tracing 实现分布式调用链路追踪，自动透传 TraceId、写入响应头，并通过 MDC 关联日志。
---

`continew-starter-trace` 是 ContiNew Starter 的链路追踪模块，底层基于 Spring Boot 官方追踪门面 [Micrometer Tracing](https://micrometer.io/docs/tracing) 实现。模块内置 Brave 桥（`micrometer-tracing-bridge-brave`），使用方引入后即可获得请求级链路 ID、W3C 标准传播头与 MDC 日志关联，无需再自行选型桥接实现。

主要特性：

- 自动为 Web 请求创建或透传链路上下文，传播格式为 W3C `traceparent`
- 将当前链路 ID 写入响应头，便于前端获取整条链路的标识
- 通过 MDC 提供 `traceId`、`spanId`，日志框架按需引用即可关联全链路
- 桥缺失时启动即失败，不会静默丢失链路信息
- 采样率默认全采样，可按需覆盖

## 引入依赖

```xml
<dependency>
    <groupId>top.continew.starter</groupId>
    <artifactId>continew-starter-trace</artifactId>
</dependency>
```

## 配置

```yaml
continew-starter:
  trace:
    # 是否启用链路追踪（默认 false）
    enabled: true
    # 写入响应头的链路 ID 名称（默认 traceId）
    trace-id-name: X-Trace-Id

# 采样率由 Spring Boot 管理，未显式配置时模块补为 1.0（全采样）
management:
  tracing:
    sampling:
      probability: 1.0
```

配置项说明（前缀均为 `continew-starter.trace`）：

| 配置项 | 类型 | 默认值 | 说明 |
|:-------|:-----|:-------|:-----|
| `enabled` | `boolean` | `false` | 是否启用链路追踪，设为 `true` 后自动装配生效 |
| `trace-id-name` | `String` | `traceId` | 写入响应头的链路 ID 名称，留空则不写入 |

采样率、传播格式等进阶配置使用 Spring Boot 标准键 `management.tracing.*`，见 [Spring Boot 链路追踪配置](https://docs.spring.io/spring-boot/reference/actuator/tracing.html)。其中 `management.tracing.sampling.probability` 默认为 `0.1`，而本模块在启用且使用方未显式配置该键时补为 `1.0`。

<Callout type="info">
启用后，模块注册一个优先级高于常规业务过滤器的 Servlet 过滤器（`TraceResponseFilter`），在当前请求的 Span 上下文中取出链路 ID，以 `trace-id-name` 指定的名称写入响应头。链路上下文本身由 Spring Boot 的观测机制创建，模块不重复生成。
</Callout>

## 日志输出链路 ID

Micrometer Tracing 会把链路标识写入 MDC，键名为 `traceId` 与 `spanId`。日志配置中直接引用即可，不需要替换 appender 或 encoder 实现：

```xml
<!-- logback-spring.xml -->
<configuration>
    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss} %-5level [%thread] [%X{traceId}] %logger{50} - %msg%n</pattern>
            <charset>utf-8</charset>
        </encoder>
    </appender>

    <root level="INFO">
        <appender-ref ref="CONSOLE"/>
    </root>
</configuration>
```

代码中获取链路 ID 有两种方式：

```java
// 从 MDC 获取（当前线程处于请求上下文时可用）
String traceId = TraceUtils.getTraceId();

// 从 Tracer 获取（不依赖 MDC）
String traceId = TraceUtils.getTraceId(tracer);
```

## 跨服务传播

出站请求头由 Spring Boot 自动配置的 `RestClient`、`RestTemplate`、`WebClient` 构建器注入，使用 W3C `traceparent`。手工创建 HTTP 客户端（如 `HttpURLConnection`、自建 OkHttp 实例）不会自动注入传播头，需要自行透传。

入站消费格式默认兼容 `W3C`、`B3`、`B3_MULTI`，出站默认只产生 `W3C`，可通过 `management.tracing.propagation.produce` 与 `management.tracing.propagation.consume` 调整。

## 线程池与异步场景

Micrometer Tracing 的上下文不会自动跨线程传递。`@Async` 或自定义线程池需要显式装饰任务，Boot 提供 `ContextPropagatingTaskDecorator`：

```java
@Configuration
public class TraceConfig {

    @Bean
    public TaskDecorator contextPropagatingTaskDecorator() {
        return new ContextPropagatingTaskDecorator();
    }
}
```

```java
@Bean
public ThreadPoolTaskExecutor threadPoolTaskExecutor(TaskDecorator contextPropagatingTaskDecorator) {
    ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
    executor.setTaskDecorator(contextPropagatingTaskDecorator);
    return executor;
}
```

## 从 2.x 升级

模块在 3.0.0 起移除 TLog，替换为 Micrometer Tracing，有三处行为变化：

- 传播头从 `tlogTraceId`、`tlogSpanId` 改为 W3C `traceparent`，与旧版本服务混跑时链路会中断，全家桶需同版本发布
- 日志 MDC 键从 TLog 的 `tl` 改为 `traceId`、`spanId`
- `TLogIdGenerator` 扩展点删除，自定义链路 ID 生成改用 Micrometer 的 `Sampling`、`Propagator` 或桥实现配置

旧版 `continew-starter.trace.tlog.*` 配置项仍可绑定（避免升级后启动失败），但自 3.0.0 起不再生效，启用时启动日志会输出一条 WARN 提示移除。下表保留这些键仅为升级参考。

| 配置项 | 类型 | 说明 |
|:-------|:-----|:-----|
| `tlog.pattern` | `String` | 已移除，改用日志 pattern 中的 `%X{traceId}` |
| `tlog.enable-invoke-time-print` | `Boolean` | 已移除 |
| `tlog.mdc-enable` | `Boolean` | 已移除，MDC 关联由 Boot 默认提供 |
| `tlog.id-generator` | `String` | 已移除，原配置项在 2.x 中也未被读取 |

## 注意事项

- 模块只在 Web 应用（Servlet 环境）中生效，非 Web 应用不注册过滤器。
- `enabled: true` 但类路径缺少可用桥时启动直接失败，报错信息会指明检查 `micrometer-tracing-bridge-brave`。这是为避免链路能力静默失效。
- 模块自动装配不依赖 `spring-boot-starter-actuator`，也不默认上报任何后端；需要接入 Zipkin 或 OTLP 时按 Spring Boot 文档追加对应依赖。
- 引入本模块后，Micrometer Tracing 的自动装配即随依赖生效，`continew-starter.trace.enabled` 控制的是响应头写入与采样率默认值。
