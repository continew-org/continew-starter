ContiNew Starter（Continue New Starter）基于「约定优于配置」理念，进一步精简常规配置，提供完整的配置解决方案，帮助开发人员更快速地将常用第三方库或工具集成到 Spring Boot Web 应用程序中。

它封装了一系列经过企业实践验证的依赖包（如 MyBatis-Plus、Sa-Token、Redisson、JetCache 等），可轻松集成到应用中，减少手动引入依赖及配置的工作量，为 Spring Boot Web 项目的灵活快速构建提供支持。

## 解决什么问题

在 Spring Boot 项目中集成一个成熟组件，通常要经历：查依赖坐标 → 引入正确版本 → 编写配置类 → 调参 → 处理版本冲突。当项目里有十几个这样的组件时，这套重复劳动既繁琐又容易出错。

ContiNew Starter 把这套流程收敛为**引入一个 Starter、配置几个属性**：

- **统一的依赖管理**：全部第三方依赖版本由 `continew-starter-dependencies` 统一供给，你无需关心版本号，也无需担心组件间的版本冲突；
- **开箱即用的自动配置**：每个模块通过 Spring Boot 3 的 `AutoConfiguration.imports` 机制注册，引入即生效，无需手写配置类；
- **约定优于配置**：合理的默认值让你多数情况下「零配置」可用，需要定制时再以 `continew-starter.<module>` 前缀的属性覆盖；
- **企业实践验证**：封装的组件与默认参数来自真实企业项目实践，而非简单包装。

## 环境要求

| 要求 | 版本 |
|:-----|:-----|
| JDK | 17+ |
| Spring Boot | 3.x |
| 构建工具 | Maven 3.9+（或等效 Gradle） |

<Callout type="info">
ContiNew Starter 2.x 基于 Spring Boot 3.x 与 JDK 17。仍在使用 Spring Boot 2.x 的项目请参考历史版本文档。
</Callout>
